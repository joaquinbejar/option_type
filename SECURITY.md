# Security Policy

## Reporting a vulnerability

**Please report security vulnerabilities privately. Do not open a public
issue, pull request, or discussion for a suspected vulnerability.**

Use either of the following private channels:

1. **GitHub Security Advisories (preferred)** — open a private report via the
   ["Report a vulnerability"](https://github.com/joaquinbejar/option_type/security/advisories/new)
   button on the repository's **Security** tab. This keeps the report
   confidential and lets us coordinate a fix and disclosure with you.
2. **Email** — <jb@taunais.com>.

When reporting, please include as much of the following as you can:

- The affected version(s) of `option_type`.
- A description of the vulnerability and its impact.
- Steps to reproduce, or a minimal proof of concept.
- Any suggested mitigation or fix, if you have one.

## Supported versions

Only the latest published minor version receives security fixes. Older minors
are not patched — upgrade to the latest release to stay supported.

| Version | Supported |
|---------|-----------|
| latest published minor (currently `0.1.x`) | ✅ |
| any older minor | ❌ |

## Disclosure process

- **Acknowledgment:** we aim to acknowledge your report within **7 days**.
- **Fix or mitigation:** we target a fix or mitigation within **90 days** of
  acknowledgment, depending on severity and complexity.
- **Coordinated disclosure:** we practice coordinated disclosure. We will work
  with you on the timing of any public advisory and, unless you prefer
  otherwise, credit you in the release notes and advisory once a fix is
  available. Please keep the report confidential until a fix has been published.
